# 项目资源清单

## 目标

明确语音日历 Agent 开发和上线需要调用、准备或接入的资源，避免开发过程中临时找服务、申请密钥或改变架构。

## 资源分级

- 必需：没有该资源，核心版本无法开发或演示。
- 推荐：能明显提升体验或开发效率，但可以降级。
- 可选：适合后续增强，一天内上线不强依赖。

## 推荐最小资源组合

一天内上线建议采用以下组合：

```text
React + Vite + TypeScript
Tailwind CSS
date-fns
lucide-react
Web Speech API
SpeechSynthesis API
localStorage
Vercel / Netlify
可选 AI 文本解析接口
```

这个组合的优势：

- 不需要后端即可上线。
- 不需要第三方日历 OAuth。
- 语音能力可以直接在浏览器中完成。
- AI 接口可以作为增强，不影响基础功能。
- 现场演示失败时可以降级到文字输入。

## AI 接口使用策略

AI 接口不要作为唯一解析方式。

推荐策略：

1. 本地规则解析先处理高频日程表达。
2. 规则解析失败或置信度低时，再调用 AI 接口。
3. AI 必须返回严格 JSON。
4. AI 解析结果必须经过用户确认后才能写入日历。
5. AI 调用失败时，提示用户换一种说法，不影响基础功能。

### 建议 AI 输出格式

```json
{
  "intent": "create_event",
  "title": "产品评审会",
  "start": "2026-05-31T15:00:00+08:00",
  "end": "2026-05-31T16:00:00+08:00",
  "location": "",
  "reminderMinutes": 10,
  "confidence": 0.92,
  "missingFields": []
}
```

## 环境变量建议

如果接入 AI 接口，建议使用：

```text
VITE_AI_PROVIDER=openai
VITE_AI_API_KEY=your_api_key
VITE_AI_MODEL=gpt-4.1-mini
VITE_AI_BASE_URL=https://api.openai.com/v1
```

如果部署到公开环境，不建议把真实密钥直接放在前端环境变量中。生产版本应使用后端代理接口保护密钥。一天内演示版本可以先关闭 AI 接口，或只在本地使用。

## 是否需要服务器

第一版不需要服务器。

原因：

- 语音识别使用浏览器能力。
- 日历数据存储在本地。
- Agent 基础解析可以在前端完成。
- 静态前端即可部署。

需要服务器的情况：

- 要保护 AI API Key。
- 要做用户登录。
- 要多端同步。
- 要接入 Google Calendar / Outlook。
- 要保存云端日历数据。

## 最终建议

短期开发不要把资源链路拉太长。

第一版采用纯前端架构：

```text
浏览器语音识别 -> 前端 Agent 解析 -> 本地日历数据 -> 日历 UI 展示 -> 浏览器语音播报
```

这样开发速度最快，部署最简单，现场演示风险最低。
