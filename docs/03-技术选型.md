# 技术选型

## 推荐方案

短期内开发上线，推荐使用：

- 前端：React + Vite + TypeScript
- 样式：Tailwind CSS
- 状态管理：Zustand 或 React Context
- 日期处理：date-fns
- 语音识别：浏览器 Web Speech API
- 语音播报：浏览器 SpeechSynthesis API
- 数据存储：localStorage 起步，必要时升级 IndexedDB
- Agent 解析：本地规则解析优先，可选接入 LLM JSON 解析
- 部署：Vercel / Netlify / 静态服务器

## 选择理由

React + Vite 启动快、生态成熟，适合一天内做出可演示的 Web Agent 应用。语音能力优先使用浏览器原生 API，可以减少服务端依赖和部署风险。日历数据先做本地持久化，能保证核心体验完整闭环。

## 架构分层

- `ui`：语音按钮、文本输入、对话区、日历视图、事件详情。
- `agent`：意图识别、时间解析、追问、确认状态机。
- `calendar`：事件 CRUD、范围查询、冲突检测、撤销。
- `speech`：语音识别和语音播报封装。
- `storage`：本地持久化。

## API Key 策略

默认版本不依赖外部 LLM API，避免现场网络和密钥风险。若后续接入 LLM，必须满足：

- 返回严格 JSON。
- 解析失败自动回退本地规则。
- 所有写入类操作仍需用户确认。

## 浏览器兼容策略

Web Speech API 在不同浏览器支持不一致，因此：

- 推荐 Chrome 演示。
- 麦克风不可用时自动切到文字输入。
- 语音播报失败不影响日程操作。
