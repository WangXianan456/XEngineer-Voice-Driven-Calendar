# 风险预案

## 目标

提前估计一天内开发语音日历 Agent 可能遇到的问题，并给出降级方案，保证作品能按时上线和稳定演示。

## 主要风险

| 风险 | 可能表现 | 严重程度 | 预案 |
| --- | --- | --- | --- |
| Web Speech API 不可用 | 浏览器不支持语音识别，或麦克风权限失败 | 高 | 保留文字输入；推荐 Chrome；页面展示语音状态 |
| 语音识别中文不准 | 「三点」识别成「山点」或漏掉提醒 | 高 | 识别后展示文本，允许用户编辑再提交 |
| 中文时间解析错误 | 明天、下周、下午时间被解析错 | 高 | 只覆盖高频表达；写入前必须确认结构化结果 |
| 删除误操作 | 删除了错误事件 | 高 | 删除必须二次确认；支持撤销最近操作 |
| 修改找不到事件 | 用户说「把那个会改到四点」但上下文不足 | 中 | 优先使用最近事件上下文；找不到时列出候选让用户选择 |
| 事件冲突 | 同一时间安排多个会议 | 中 | 添加前检测重叠事件并提示 |
| LLM API 不稳定 | 网络、密钥、格式错误影响解析 | 中 | 默认本地规则解析；LLM 只做增强 |
| UI 完成度不足 | 看起来像聊天 Demo，不像日历工具 | 中 | 首屏必须有日历视图、今日安排、语音入口 |
| 部署时间不足 | 构建失败或环境变量缺失 | 中 | 不依赖服务端；优先静态部署 |
| 移动端兼容问题 | 手机端麦克风或布局异常 | 中 | 以桌面 Chrome 演示为主；移动端做基本响应式 |

## 降级策略

### 语音失败

保留完整文字输入能力。演示时可以说：

> 当前浏览器未开放语音权限，系统已自动切换到文字指令模式，Agent 能力不受影响。

### 时间解析不确定

不要直接写入日历，进入确认或追问：

- 「我理解的是明天下午 3 点到 4 点，是否确认？」
- 「你说的是上午 3 点还是下午 3 点？」

### 查询结果过多

不要一次性展示全部事件，只展示摘要：

- 今天共有 5 个安排。
- 先展示最近 3 个。
- 提供「查看全部」。

### 删除匹配多个事件

列出候选项，让用户选择：

- 「我找到了 2 个明天的产品会，请选择要删除哪一个。」

### LLM 不可用

产品仍然可演示：

- 本地规则解析覆盖主要演示指令。
- 复杂表达提示用户换一种说法。

## 必须提前测试的指令

- 明天下午三点开产品评审会，提前十分钟提醒我。
- 我明天有什么安排？
- 把产品评审会改到下午四点。
- 删除明天的产品评审会。
- 明天下午我什么时候有空？
- 下周一上午十点和设计团队开会。
- 今天晚上八点提醒我复盘项目。

## 最坏情况可交付版本

如果时间严重不足，必须保留：

- 文字指令输入。
- 日历事件增删改查。
- 本地存储。
- 添加和删除前确认。
- 今日 / 本周事件视图。

即使语音识别不能稳定运行，这个版本仍然是一个可演示的日历 Agent。
