# 演示视频方案

## 视频定位

目标时长：4 到 5 分钟。

核心表达：

```text
这是一个本地优先、LLM 增强、状态机驱动、带评测和安全校验的语音日历 Agent。
```

不要把视频拍成普通功能流水账。重点是证明三件事：

- 用户体验完整：语音 / 文字输入到日历操作闭环。
- Agent 可信：写操作必须确认，删除和修改有安全边界。
- 工程质量可展示：评测集、validator、接口级回归和多轮 Memory。

## 录制准备

环境：

- Chrome 浏览器。
- 前端地址：`http://127.0.0.1:5173`。
- 默认语音模式：浏览器识别。
- 本地 Whisper 只展示为可选开关，不作为现场硬依赖。

录制前命令：

```bash
npm run test
npm run eval:parser
npm run build
conda run -n base python -m unittest discover -s backend\tests -p "test_*.py"
```

页面准备：

1. 打开页面。
2. 点击「清空本地数据」。
3. 确认顶部显示「浏览器识别」。
4. 确认 Agent 确认区、月历、日程列表可见。
5. 如果语音识别不稳定，改用文字输入录制，旁白说明语音是默认入口、文字是兜底。

## 分镜脚本

### 1. 开场定位，20 秒

画面：

- 展示完整页面首屏。
- 鼠标指向语音入口、确认区、月历。

旁白：

> 这是一个语音日历 Agent。用户不用打开复杂表单，只要说一句自然语言，系统会解析时间、标题、提醒和操作类型。但它不是让模型直接改日历，所有新增、修改、删除都会先进入确认状态机。

展示重点：

- 页面不是聊天框，是日历工作台。
- 默认是浏览器识别。
- 写操作有确认区。

### 2. 核心闭环，90 秒

操作 1：

```text
明天下午三点开产品评审会，提前十分钟提醒我
```

点击确认。

旁白：

> 系统把一句中文口语解析成结构化日程：标题、时间和提醒都被抽取出来。确认前不会写入日历，确认后才进入本地日历状态。

操作 2：

```text
我明天有什么安排
```

旁白：

> 查询操作不会改变状态，所以可以直接返回明天的日程摘要。

操作 3：

```text
把产品评审会改到下午四点
```

点击确认。

旁白：

> 这里用户没有重复日期，系统会根据匹配到的原日程沿用明天这个日期，只修改时间。

操作 4：

```text
明天下午四点半安排一个设计评审
```

点击取消。

旁白：

> 新日程和已有会议冲突，系统会在确认卡片里提示，而不是静默写入。

操作 5：

```text
删除明天的产品评审会
```

点击确认，再输入：

```text
撤销
```

旁白：

> 删除是高风险操作，必须二次确认。确认删除后，还能撤销最近一次操作。

### 3. 多轮 Memory，60 秒

从已经存在产品评审会的状态开始。

操作 1：

```text
提醒也提前十五分钟
```

点击确认。

操作 2：

```text
把地点改成 A 楼
```

点击确认。

操作 3：

```text
刚才那个取消
```

点击确认。

旁白：

> 这段展示短期 Memory。用户不用每次重复“产品评审会”，Agent 会记住最近提到的日程，并把“也”“刚才那个”这类上下文指代表达绑定到正确事件。高风险删除仍然进入确认。

展示重点：

- Memory 不是长文本记忆，只保存必要上下文。
- 省略表达能工作。
- 高风险操作仍受状态机约束。

### 4. 安全和校验，45 秒

画面：

- 展示确认卡片。
- 简短切到代码或 README 当前状态。

旁白：

> 可信性是这个项目的重点。前端有 deterministic validator，会拦截非法时间、非法提醒和不安全候选。后端 DeepSeek 兜底返回的 JSON 也要经过 schema 和语义校验；非法 JSON、缺目标删除、非法时间都会降级成追问，不会进入确认卡片。

展示重点：

- LLM 只负责解析建议。
- validator 和状态机决定是否能进入确认。
- 删除 / 修改不允许绕过确认。

### 5. 工程质量，45 秒

画面：

- 终端运行或展示最近已通过结果。

命令：

```bash
npm run test
npm run eval:parser
conda run -n base python -m unittest discover -s backend\tests -p "test_*.py"
```

旁白：

> 解析质量不是靠感觉判断。项目有 55 条中文口语评测集，输出 intent accuracy、slot accuracy、fallback rate 和 unsafe action rate。前端测试覆盖解析器、状态机、validator 和 Memory；后端测试覆盖 DeepSeek 输出校验和 `/api/parse-command` 接口边界。

展示重点：

- 55 cases。
- unsafe action rate 0%。
- 前后端测试都通过。

### 6. 收尾，20 秒

画面：

- 回到产品页面。

旁白：

> 这个版本已经打通语音输入、自然语言解析、确认状态机、日历操作、多轮上下文和解析评测。后续可以继续扩展真实日历同步、智能排期和提醒任务。

## 推荐录制顺序

为了减少失误，建议按这个顺序录：

1. 先录产品功能主路径。
2. 再录 Memory 多轮路径。
3. 再录终端测试结果。
4. 最后补录开场和收尾。

如果一次录到底，建议直接使用文字输入，保证节奏稳定。

## 失败预案

语音识别失败：

- 改用文字输入。
- 旁白说明浏览器语音是默认入口，文字是稳定兜底。

后端不可用：

- 不影响主路径。
- 旁白说明 DeepSeek 是 unknown 时的可选增强，本地规则仍可闭环。

录制时页面状态错乱：

- 点击「清空本地数据」。
- 重新从新增产品评审会开始。
