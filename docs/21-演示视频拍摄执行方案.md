# 演示视频拍摄执行方案

## 方案定位

本文件是 `20-演示视频方案` 的执行补充版。前者解决“讲什么”，本文件解决“怎么拍、怎么剪、怎么让评审在 5 分钟内看懂技术含量”。

推荐成片目标：

```text
4 分 30 秒以内，先证明产品闭环，再证明 Agent 可信，最后证明工程质量。
```

不建议把视频拍成完整答辩稿朗读。视频要让画面承担功能证明，旁白只解释画面背后的工程判断。

## 推荐成片结构

| 段落 | 时长 | 画面 | 目标 |
| --- | ---: | --- | --- |
| 1. 一句话定位 | 0:00-0:15 | 产品首屏 + 语音入口 + 日历区 | 让评审立刻知道这是语音日历 Agent |
| 2. 主路径闭环 | 0:15-1:45 | 新增、查询、修改、删除、撤销 | 证明自然语言到日历操作可闭环 |
| 3. 安全确认机制 | 1:45-2:30 | 确认卡片、冲突提示、删除确认 | 证明不是让 LLM 直接改数据 |
| 4. 多轮 Memory | 2:30-3:20 | 省略表达、地点/提醒修改、刚才那个 | 证明 Agent 能处理上下文 |
| 5. 工程质量 | 3:20-4:10 | 测试、评测集、validator 代码或 README 状态 | 证明项目不是一次性 Demo |
| 6. 收尾总结 | 4:10-4:30 | 回到完整工作台 | 总结已完成能力和可扩展方向 |

如果只能录 3 分钟，保留 1、2、3、5，删掉或压缩 Memory 段。

## 推荐镜头资产

录制前准备 5 类素材：

1. 产品首屏：显示语音入口、文字兜底、确认区、月历、日程列表。
2. 主路径操作：新增、查询、修改、删除、撤销。
3. 风险路径操作：冲突日程、取消确认、删除二次确认。
4. Agent 能力操作：省略主语修改提醒、修改地点、引用“刚才那个”。
5. 工程证明：`npm run test`、`npm run eval:parser`、后端 unittest、`npm run build` 的通过结果。

屏幕比例建议：

- 录制分辨率：1920x1080。
- 浏览器缩放：90% 或 100%，以完整露出确认区和日历区为准。
- 终端字体：14 到 16，避免评测指标看不清。
- 鼠标移动慢一点，点击后停留 1 到 2 秒，让确认卡片和日历变化有时间被看见。

## 旁白压缩版

可以直接按以下旁白录音，配合剪辑画面使用。

### 开场

```text
这是一个语音日历 Agent。用户可以用中文自然语言添加、查询、修改和删除日程。它的重点不是普通 CRUD，而是把语音输入、日程解析、确认状态机、冲突检测、多轮上下文和工程评测合成一个可信闭环。
```

### 主路径

```text
我先说一句：明天下午三点开产品评审会，提前十分钟提醒我。系统会把口语解析成结构化日程，但确认前不会写入日历。点击确认后，月历和日程列表同步更新。

接着查询：我明天有什么安排。查询是只读操作，可以直接返回摘要。

然后修改：把产品评审会改到下午四点。这里用户没有重复日期，Agent 会根据目标日程沿用原日期，只修改时间。

最后删除并撤销。删除是高风险操作，必须经过确认；误删后可以撤销最近一次操作。
```

### 安全机制

```text
这个项目没有让模型直接操作日历。所有新增、修改、删除都会先进确认卡片。前端 deterministic validator 会拦截非法时间、非法提醒和不安全候选；后端 DeepSeek 兜底返回的 JSON 也要通过 schema 和语义校验，失败就降级成追问。
```

### 多轮 Memory

```text
多轮 Memory 只保存必要上下文。用户可以说“提醒也提前十五分钟”“把地点改成 A 楼”“刚才那个取消”，系统会绑定到最近相关日程，但真正写入前仍然经过确认。
```

### 工程质量

```text
解析质量不是靠现场感觉判断。项目有中文口语评测集，覆盖新增、查询、修改、删除、空闲时间、下周范围、安全候选和降级输入。前端测试覆盖解析器、状态机、validator 和 Memory；后端测试覆盖 DeepSeek 输出校验和接口边界。
```

### 收尾

```text
这个版本已经完成语音输入、自然语言解析、确认状态机、本地日历操作、多轮上下文、后端 AI 兜底和解析评测。后续可以扩展真实日历同步、智能排期和提醒任务。
```

## 操作脚本

录制时建议只使用以下 8 条输入，减少口误和状态漂移。

```text
明天下午三点开产品评审会，提前十分钟提醒我
我明天有什么安排
把产品评审会改到下午四点
明天下午四点半安排一个设计评审
删除明天的产品评审会
撤销
提醒也提前十五分钟
把地点改成 A 楼
```

推荐执行顺序：

1. 点击「清空本地数据」。
2. 输入新增产品评审会，确认。
3. 输入查询明天安排。
4. 输入修改到下午四点，确认。
5. 输入设计评审冲突，展示提示后取消。
6. 输入删除产品评审会，确认。
7. 输入撤销，确认产品评审会回到日历。
8. 输入提醒提前十五分钟，确认。
9. 输入地点改成 A 楼，确认。

如果要展示“刚才那个取消”，建议单独录一小段，不要放在主路径中间，避免评审把它理解成误操作。

## 剪辑建议

画面节奏：

- 输入文字可以加速到 1.5x，但确认卡片出现和日历变化不要加速。
- 每个关键结果停留至少 1 秒。
- 终端测试结果只保留最终通过行和指标行，不展示长滚动过程。
- 不要频繁切代码；代码只作为 validator 和评测存在的证据。

字幕建议：

- 每段只放一句短字幕，例如“写操作先确认”“冲突不静默写入”“55 条评测集”。
- 不要把完整旁白做成大段字幕。
- 避免遮挡确认卡片、日历事件和终端指标。

转场建议：

- 产品操作段使用直接剪切。
- 从产品切到终端时加 0.3 秒淡入即可。
- 不使用复杂动画，避免显得像包装多于工程。

## 评审关注点对齐

作品完整度：

- 语音 / 文字输入都可用。
- 日历 CRUD 闭环完整。
- 页面是工作台，不是普通聊天框。

创新性：

- 自然语言日历 Agent。
- 多轮上下文省略表达。
- 冲突检测、撤销和确认状态机。

开发质量：

- 本地规则优先，AI 兜底增强。
- 前端和后端都有 deterministic validation。
- 有评测集和自动化测试结果。

演示表达：

- 先展示可用产品，再解释技术含量。
- 少讲架构名词，多展示“错误输入不会直接写入”的可信行为。
- 用测试和评测指标收尾，避免视频只像产品广告。

## 录制前检查

- [ ] 清空本地数据，状态从零开始。
- [ ] 不展示 `.env`、`.env.local` 或任何真实 key。
- [ ] 浏览器地址栏不包含敏感参数。
- [ ] 前端页面没有打开开发者工具错误面板。
- [ ] 文字输入可兜底完成全流程。
- [ ] 删除、修改、新增都进入确认卡片。
- [ ] 冲突场景能展示提示并取消。
- [ ] 测试输出提前跑通，终端保留干净结果。
- [ ] 视频总时长控制在 4 分 30 秒以内。

## 推荐最终版本

优先提交一个“稳态版”视频：

```text
文字输入录制主路径 + 旁白说明语音是默认入口 + 产品首屏显示浏览器识别状态 + 终端展示测试和评测通过。
```

原因：

- 文字输入能显著降低录制不确定性。
- 页面仍能证明语音入口和语音模式存在。
- 评审更关心 Agent 闭环和工程可信度，不会因为现场语音识别波动影响观感。

如果有额外时间，再补一个 20 到 30 秒的真实语音输入片段放在开头，作为体验亮点。
