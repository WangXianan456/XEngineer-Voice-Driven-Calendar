# 技术含量提升路线图

## 目标

当前项目已经完成可演示的语音日历 Agent：

```text
语音 / 文字输入
-> 本地规则 + DeepSeek 兜底解析
-> 确认 / 候选选择
-> localStorage 日历
-> 月历视图
```

下一阶段目标不是继续堆 UI，而是把项目升级成更像真实产品和真实 Agent 系统的工程形态：

- 行为可解释。
- 状态可控。
- 解析可评测。
- 高风险操作可审计。
- 外部服务失败可降级。

## 总体路线

```text
阶段 8：Agent 状态机重构
阶段 9：解析器评测集与混合解析器
阶段 10：多轮上下文 Memory
阶段 11：语音质量工程
阶段 12：真实日历同步
阶段 13：智能排期和冲突推荐
阶段 14：提醒任务与可观测性
```

推荐优先顺序：

1. Agent 状态机重构。
2. 解析器评测集。
3. 多轮上下文 Memory。
4. 语音质量工程。
5. 真实日历同步。
6. 智能排期。
7. 提醒任务和监控。

## 阶段 8：Agent 状态机重构

### 要解决的问题

当前确认、候选选择、撤销和解析流程主要写在 `App.tsx` 中。功能已经可用，但后续继续增加多轮对话会让条件分支复杂化。

### 目标状态机

```text
idle
-> listening
-> transcribing
-> parsing
-> awaiting_confirmation
-> awaiting_candidate_selection
-> executing
-> completed
-> failed
```

### 任务

- 新增 `src/agent/agentStateMachine.ts`。
- 把 pending action、candidate selection、confirm/cancel/undo 从组件中抽离。
- 定义事件：
  - `USER_COMMAND`
  - `PARSE_SUCCESS`
  - `PARSE_FAILED`
  - `SELECT_CANDIDATE`
  - `CONFIRM`
  - `CANCEL`
  - `EXECUTE_SUCCESS`
  - `EXECUTE_FAILED`
- 组件只负责渲染状态和分发事件。

### 验收

- 删除 / 修改 / 新增 / 取消 / 撤销路径都通过。
- 多候选选择不依赖 UI 组件内部临时逻辑。
- 状态转换有单元测试。

## 阶段 9：解析器评测集与混合解析器

### 要解决的问题

现在本地规则有测试，但没有系统性评测集；DeepSeek 兜底也没有稳定的质量指标。

### 目标架构

```text
本地规则解析
-> DeepSeek JSON 解析
-> deterministic validator
-> confirmation action
```

### 任务

- 新增 `tests/fixtures/command-cases.json`。
- 每条样例包含：
  - `input`
  - `now`
  - `events`
  - `expectedIntent`
  - `expectedAction`
  - `expectedMissingFields`
  - `expectedSafety`
- 增加评测脚本：
  - intent accuracy
  - slot accuracy
  - time parse accuracy
  - unsafe action rate
  - fallback rate
- 增加 JSON Schema / Zod 校验。
- LLM 输出必须经过 validator 才能进入确认卡片。

### 验收

- 至少 50 条中文口语日程语料。
- 本地规则测试和 LLM 兜底测试分开统计。
- 删除 / 修改类操作 unsafe action rate 为 0。

## 阶段 10：多轮上下文 Memory

### 要解决的问题

当前只记录最近一个被提到的事件，支持基础“它 / 那个 / 刚才那个”。真实多轮对话需要更完整的短期上下文。

### 目标 Memory

```ts
type AgentMemory = {
  lastIntent: string | null;
  lastMentionedEvents: CalendarEvent[];
  lastCandidates: CalendarEvent[];
  pendingClarification: string | null;
  selectedEventId: string | null;
  conversationSummary: string;
};
```

### 任务

- 新增 `src/agent/agentMemory.ts`。
- 支持：
  - “不是这个，是第二个”
  - “把地点改成 A 楼”
  - “提醒也提前十五分钟”
  - “刚才那个取消”
  - “改成明天下午”
- Memory 只保存必要上下文，不保存敏感长文本。

### 验收

- 多轮修改测试不少于 10 条。
- 无上下文时必须追问，不默认猜测。
- 高风险操作仍然必须确认。

### 当前推进状态

已完成：

- 已新增 `src/agent/agentMemory.ts`，Memory 保存最近意图、最近提到日程、候选列表、待澄清状态、选中事件和简短摘要。
- 已接入状态机，查询、删除、修改候选会进入 Memory，多候选可通过“第一个 / 第二个”和“不是这个，是第二个”改选。
- 已支持基于上下文的提醒省略修改，例如“提醒也提前十五分钟”。
- 已支持基于上下文的地点省略修改，例如“把地点改成 A 楼”。
- 已支持基于上下文的删除表达，例如“刚才那个取消”，仍然会进入删除确认。
- 已补充“改成明天下午 / 改到后天 / 改到下周三下午四点半”这类不完整时间修改：有上下文时沿用最近日程，缺少具体钟点时使用确定性时段默认值；无上下文时不猜测，继续追问。
- 已补充 Memory 单元测试，覆盖候选记忆、候选改选、上下文引用、提醒 / 地点 / 时间省略修改和无上下文边界。

剩余可继续增强：

- 把 Memory 摘要展示到调试面板，便于演示时解释 Agent 当前上下文。
- 给多轮对话增加端到端浏览器测试，覆盖“查询 -> 第二个 -> 改提醒 -> 改时间 -> 取消”的完整链路。

## 阶段 11：语音质量工程

### 要解决的问题

浏览器识别效果好但不可控，本地 Whisper 可控但当前 `base/int8` 中文识别一般。

### 任务

- 保留双模式：
  - 浏览器识别：默认演示路径。
  - 本地 Whisper：本地免费能力和离线能力。
- 增加语音纠错层：
  - “产品平审会” -> “产品评审会”
  - “题型” -> “提醒”
  - 常用人名、项目名、会议名热词。
- 增加 ASR 结果确认：
  - 低置信度或空结果时先把文本放入输入框。
  - 用户可编辑后发送。
- 修复本地 VAD：
  - 解决 `onnxruntime` DLL 问题。
  - 恢复 `vad_filter=True`。
- 模型策略：
  - 默认 `base / cpu / int8`。
  - GPU 主机支持 `small / cuda / float16`。

### 验收

- 浏览器识别路径稳定可演示。
- 本地 Whisper 至少能稳定识别 5 条标准演示语句。
- ASR 失败时文字输入不受影响。

### 当前推进状态

已完成：

- 已保留双模式：浏览器识别仍是默认演示路径，本地 Whisper 通过 `VITE_API_BASE_URL` 可选启用。
- 已新增前端语音纠错层 `src/speech/speechCorrection.ts`，覆盖常见中文 ASR 误识别热词，例如“产品平审会 / 产品凭审会 -> 产品评审会”“题型 / 题醒 -> 提醒”。
- 浏览器识别结果会先经过纠错层，再按原演示路径自动提交，保证主路径速度。
- 本地 Whisper 结果会携带 `languageProbability`，前端对低置信度、空结果、纠错后的本地 ASR、缺少日历指令线索的文本先放入输入框，由用户检查后再发送。
- 已补充语音纠错单元测试，覆盖热词纠错、低置信度确认、空结果确认和非日历指令确认。

剩余可继续增强：

- 录制 5 条标准演示语音样本，建立本地 Whisper 手工验收表。
- 恢复 `vad_filter=True` 前，先解决本地 `onnxruntime` DLL 依赖问题。
- 支持项目名、人名、会议名可配置热词表，而不是写死在前端规则中。

## 阶段 12：真实日历同步

### 要解决的问题

localStorage 只能支持单机演示，不能成为真实日历产品。

### 任务

- 先实现 ICS 导入 / 导出。
- 再评估 Google Calendar / Outlook：
  - OAuth 登录。
  - token 存储。
  - external_event_id 映射。
  - 增删改同步。
  - 冲突和重复事件处理。
- 后端新增 `calendar_events` 存储层。

### 验收

- 本地事件可导出 ICS。
- 外部日历导入后能在月历中展示。
- 修改 / 删除外部事件必须二次确认。

### 当前推进状态

已完成：

- 已新增 `src/calendar/ics.ts`，支持把本地日程导出为标准 `VCALENDAR / VEVENT` 格式。
- 已支持 ICS 导入，解析 `UID`、`DTSTART`、`DTEND`、`SUMMARY`、`LOCATION`、`DESCRIPTION` 和 `VALARM TRIGGER`。
- 已在事件模型中增加 `externalSource` 和 `externalEventId`，为后续 Google Calendar / Outlook 同步映射做准备。
- 已在本地导入时按 `externalSource + externalEventId` 去重；没有外部 ID 时按标题和时间去重。
- 已在页面增加“导出 ICS / 导入 ICS”入口，保留 JSON 导出作为调试能力。
- 已在日程列表、候选选择和确认卡片中展示事件来源，本地事件显示“本地”，ICS 导入事件显示“ICS”。
- 已增强 ICS 导入反馈，能区分非完整 ICS 文件、无有效事件、重复事件和无效事件。
- 外部导入事件进入同一套本地事件列表，后续修改 / 删除仍走现有确认状态机。
- 已补充 ICS 单元测试，覆盖导出、导入和转义字符往返。

剩余可继续增强：

- 增加外部日历事件的来源筛选和导入批次回滚。
- 评估 Google Calendar / Outlook OAuth，同步时复用 `externalEventId` 映射。

## 阶段 13：智能排期和冲突推荐

### 要解决的问题

现在冲突检测只提示有重叠，不会主动给解决方案。

### 任务

- 支持会议时长推断。
- 工作时间偏好：
  - 工作日 09:00-18:00。
  - 午休时间避让。
  - 晚间个人时间避让。
- 冲突时推荐 2-3 个替代时间。
- 支持：
  - “帮我找明天下午一小时空档”
  - “这周找个两小时做复盘”
  - “避开已有会议安排产品评审”

### 验收

- 冲突新增时给出替代时间。
- 空闲时间查询支持时长约束。
- 推荐结果不跨越已有事件。

## 阶段 14：提醒任务与可观测性

### 要解决的问题

当前提醒只是事件字段，没有真实通知能力；Agent 解析质量也缺少运行数据。

### 任务

- 浏览器 Notification API。
- 可选 Web Push。
- 后端 reminder job。
- 增加可观测字段：
  - command_text_hash
  - parser_source
  - intent
  - confidence
  - validation_result
  - execution_status
- 增加本地 debug 面板或导出日志。

### 验收

- 日程提醒能触发浏览器通知。
- 解析失败和后端失败可定位。
- 不记录明文敏感日程内容，或提供关闭日志选项。

## 近期执行计划

### 下一轮优先做：阶段 8

原因：

- 当前功能已经开始复杂。
- 状态机能为多轮上下文、候选选择和真实日历同步打基础。
- 这是最能体现 Agent 工程能力的升级。

执行顺序：

1. 提取 `PendingAction` 和状态类型。
2. 新建状态机 reducer。
3. 把 `confirm/cancel/selectCandidate/undo` 迁入 reducer。
4. 给状态转换补测试。
5. `App.tsx` 只保留 UI 渲染和事件分发。

### 阶段 8 完成后再做：阶段 9

原因：

- 没有评测集，后续 prompt 和规则会越改越不可控。
- 评测集能为答辩提供非常强的工程质量证明。

## 技术亮点表达

最终答辩可以表达为：

```text
这是一个本地优先、LLM 增强、状态机驱动、带评测体系的语音日历 Agent。
```

关键点：

- 不是让 LLM 直接操作日历。
- 所有写操作都进入确认状态机。
- 解析结果必须经过结构化校验。
- 语音、LLM、后端都可失败，核心日历闭环仍可用。
