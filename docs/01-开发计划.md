# 语音日历 Agent 应用开发计划

## 1. 目标定位

在一天内开发上线一个可演示、可使用的「语音版日历工具」：

- 用户可以用自然语言语音完成添加、删除、查看、修改日程和提醒。
- 系统能把语音转文字、理解时间与意图、生成结构化日程操作，并在界面中给出明确确认。
- 作品重点不是做一个完整替代商业日历的重型系统，而是做出「语音管理日历」这个核心体验的准确、顺畅和可信。

一句话定位：

> 面向高频日程管理用户的语音日历 Agent，用户只要说一句话，就能把模糊口语变成可靠的日程安排。

## 2. 真实用户需求判断

日历管理中的真实痛点：

- 输入成本高：手机或电脑上新建日程要点多次，尤其是会议、提醒、地点、参与人等信息。
- 时间表达复杂：用户常说「明天下午三点」「下周一早上」「每周五」「提前十分钟提醒」，传统表单不够自然。
- 查看需求碎片化：用户想快速问「我今天下午有什么」「明早有没有空」「下周有哪些会议」。
- 修改和删除容易出错：删除事件前需要二次确认，修改时间时需要准确找到目标事件。
- 多任务场景明显：用户可能正在开车、做饭、走路、写代码，不方便手动打开日历。
- 信任感要求高：日历是高风险个人信息，系统必须展示理解结果，并允许确认、撤销和修正。

高分作品应解决的关键体验：

- 语音输入不是装饰，而是主操作入口。
- Agent 能处理自然口语、相对时间、缺省信息追问、多轮修正。
- 每次写入日历前有清晰确认，降低误操作。
- 有可视化日历和事件列表，方便评委快速理解产品能力。

## 3. MVP 功能范围

### 必做功能

1. 语音输入
   - 点击麦克风开始录音。
   - 使用浏览器 Web Speech API 做语音转文字。
   - 同步支持文字输入，避免浏览器或麦克风环境影响演示。

2. Agent 意图理解
   - 支持添加事件：如「明天下午三点和张三开产品会，提前十分钟提醒」。
   - 支持查看事件：如「我今天下午有什么安排」「查看下周日程」。
   - 支持删除事件：如「删除明天三点的产品会」。
   - 支持修改事件：如「把明天三点的产品会改到四点」。
   - 支持提醒设置：提前 5 分钟、10 分钟、30 分钟、1 小时、1 天。

3. 多轮确认
   - 信息完整时：展示结构化理解结果，让用户确认执行。
   - 信息缺失时：主动追问，如「请问是上午还是下午？」。
   - 高风险操作时：删除和批量修改必须二次确认。

4. 日历视图
   - 今日 / 本周事件列表。
   - 简单月历或周视图。
   - 事件详情展示标题、时间、地点、提醒、来源语音。

5. 本地持久化
   - 使用 localStorage 或 IndexedDB 存储事件，确保刷新不丢失。
   - 先不强依赖第三方日历账号，降低一天上线风险。

6. 演示数据和引导
   - 提供 3-5 条示例语音指令。
   - 提供一键填充演示数据，方便现场展示。

### 加分功能

- 语音播报反馈：操作成功后用 TTS 播报「已为你添加明天下午三点的产品会」。
- 冲突检测：添加事件时发现时间重叠，提示用户是否仍要添加。
- 智能空闲查询：支持「明天下午我什么时候有空」。
- 撤销操作：支持「撤销刚才的删除」。
- 导出 ICS：把本地事件导出为标准日历文件。

### 暂不做功能

- 多端同步。
- 真实 Google Calendar / Outlook OAuth 集成。
- 复杂农历、节假日和跨时区处理。
- 多人会议邀请与邮件发送。
- 完整移动端原生 App。

这些功能会显著增加接入和测试成本，不适合一天内稳定上线。可以作为后续路线图展示。

## 4. Agent 设计

### Agent 核心流程

用户语音输入：

1. Speech-to-Text：语音转文本。
2. NLU 解析：识别用户意图、时间、事件标题、地点、提醒、目标事件。
3. Calendar Tool 调用：对事件数据库执行增删改查。
4. Confirmation：写入类操作前确认，缺信息时追问。
5. Response：在聊天区、日历区、语音播报中同步反馈。

### 意图类型

- `create_event`：创建日程。
- `list_events`：查询日程。
- `update_event`：修改日程。
- `delete_event`：删除日程。
- `find_free_time`：查询空闲时间。
- `set_reminder`：设置或修改提醒。
- `unknown`：无法理解时要求用户换一种说法。

### 事件数据结构

```json
{
  "id": "evt_001",
  "title": "产品评审会",
  "start": "2026-05-31T15:00:00+08:00",
  "end": "2026-05-31T16:00:00+08:00",
  "location": "线上会议",
  "reminderMinutes": 10,
  "notes": "",
  "sourceText": "明天下午三点和张三开产品会，提前十分钟提醒",
  "createdAt": "2026-05-30T22:30:00+08:00",
  "updatedAt": "2026-05-30T22:30:00+08:00"
}
```

### 解析策略

一天内开发需要兼顾效果和确定性：

- 优先使用规则解析覆盖中文高频表达：今天、明天、后天、下周、上午、下午、晚上、几点、半点、提前几分钟。
- 对复杂自然语言保留 LLM 解析接口，返回严格 JSON。
- 若没有可用 API Key，则降级到本地规则解析，保证演示不崩。
- 对解析不确定的字段展示置信提示，并要求用户确认。

## 5. 高分作品标准

评委通常会看三件事：需求理解、核心体验、完成度。

### 需求理解

- 文档中明确真实场景：开车、会议间隙、通勤、做饭、写代码等不方便打字的场景。
- 明确语音交互价值：减少输入步骤，而不是把按钮换成麦克风。
- 明确安全机制：确认、追问、撤销、冲突提醒。

### 核心体验

- 演示路径要短：
  1. 用户说「明天下午三点开产品会，提前十分钟提醒」。
  2. Agent 展示理解结果。
  3. 用户说「确认」。
  4. 日历立即出现事件，并语音播报成功。
- 支持连续对话：
  - 「我明天有什么安排？」
  - 「把产品会改到四点」
  - 「删除它」
- 界面要让人一眼看出是日历工具，不只是聊天框。

### 完成度

- 可本地运行。
- 可部署到 Web。
- 有演示脚本。
- 有测试样例。
- 出错时有友好兜底。

## 6. 一天开发排期

### 第 0 阶段：准备，30 分钟

- 确定技术栈。
- 初始化前端项目。
- 写好事件数据结构和示例数据。
- 确定演示脚本。

产出：

- 可启动的 Web 应用骨架。
- `docs/技术选型.md`。

### 第 1 阶段：核心 UI，2 小时

- 首页直接进入语音日历工作台。
- 左侧或顶部为语音 / 文本输入区。
- 中间为 Agent 对话与确认区。
- 右侧或下方为今日、本周、月历事件视图。

产出：

- 可查看事件。
- 可展示 Agent 解析结果。

### 第 2 阶段：日历数据层，1.5 小时

- 实现事件 CRUD。
- 实现 localStorage 持久化。
- 实现按今日、本周、日期范围查询。
- 实现删除确认和撤销最近操作。

产出：

- 不依赖语音，也能用文本完整管理日程。

### 第 3 阶段：语音交互，1.5 小时

- 接入 Web Speech API 语音识别。
- 接入 SpeechSynthesis 语音播报。
- 兼容不支持语音识别的浏览器，保留文字输入。

产出：

- 可以通过语音输入指令。
- 操作结果可以语音反馈。

### 第 4 阶段：Agent 解析，3 小时

- 实现中文时间规则解析。
- 实现创建、查询、修改、删除、空闲查询意图。
- 实现缺字段追问和确认状态机。
- 可选接入 LLM JSON 解析。

产出：

- 支持 15 条以上高频中文语音指令。
- 支持多轮确认。

### 第 5 阶段：质量增强，1.5 小时

- 冲突检测。
- 示例指令。
- 演示数据。
- 错误提示和空状态。
- 响应式适配。

产出：

- 评委可快速上手。
- 现场演示抗风险。

### 第 6 阶段：测试和上线，2 小时

- 写核心解析测试样例。
- 手工跑完整演示流程。
- 修复移动端布局和麦克风权限问题。
- 部署到 Vercel / Netlify / 静态服务器。

产出：

- 可访问 URL。
- 演示脚本和 README。

## 7. 推荐演示脚本

演示时按以下顺序操作：

1. 添加日程
   - 语音：「明天下午三点开产品评审会，提前十分钟提醒我。」
   - 重点展示：语音识别、时间理解、提醒解析、确认写入。

2. 查看日程
   - 语音：「我明天有什么安排？」
   - 重点展示：自然语言查询和日历视图联动。

3. 修改日程
   - 语音：「把产品评审会改到下午四点。」
   - 重点展示：Agent 根据上下文找到目标事件。

4. 冲突检测
   - 语音：「明天下午四点半安排一个设计评审。」
   - 重点展示：发现已有会议冲突，询问是否继续。

5. 删除日程
   - 语音：「删除明天的产品评审会。」
   - 重点展示：高风险操作二次确认。

6. 空闲查询
   - 语音：「明天下午我什么时候有空？」
   - 重点展示：从日程管理升级为助理能力。

## 8. 验收标准

### 功能验收

- 能通过语音或文字添加事件。
- 能通过语音或文字查看今日、明日、本周事件。
- 能通过语音或文字删除事件，并有确认。
- 能通过语音或文字修改事件时间。
- 能设置提醒时间。
- 刷新页面后事件不丢失。

### 体验验收

- 用户说完一句话后，3 秒内看到理解结果。
- Agent 的追问明确，不让用户猜该怎么回答。
- 事件写入前用户能看到标题、时间、提醒等结构化结果。
- 日历视图和对话视图状态一致。
- 不支持语音识别时，文字输入仍可完整演示。

### 工程验收

- 一条命令可启动开发环境。
- 一条命令可构建生产包。
- 关键解析逻辑有测试样例。
- README 包含运行方式、演示指令、技术说明。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 浏览器不支持 Web Speech API | 语音演示失败 | 保留文字输入；推荐 Chrome 演示 |
| 中文时间解析不准 | 添加错误事件 | 覆盖高频规则；写入前确认 |
| LLM API 不稳定 | Agent 无法解析复杂指令 | 本地规则解析作为默认能力 |
| 一天内功能过多 | 完成度下降 | 优先 CRUD、确认、多轮、日历视图 |
| 删除误操作 | 用户不信任 | 删除必须二次确认，支持撤销 |

## 10. 开发优先级

P0：

- Web 应用骨架。
- 日历事件 CRUD。
- 文字指令解析。
- 语音输入。
- 创建、查询、删除、修改事件。
- 确认和追问。

P1：

- 语音播报。
- 冲突检测。
- 空闲时间查询。
- 演示数据和示例指令。

P2：

- ICS 导出。
- LLM 复杂解析。
- 第三方日历同步。
- 移动端专项优化。

## 11. 最小上线版本定义

上线版本必须做到：

- 打开页面即可看到语音日历工作台。
- 点击麦克风或输入文字即可下达日程指令。
- Agent 能把口语解析为结构化日程操作。
- 增删改查事件可正常工作。
- 日历视图实时更新。
- 所有写入和删除操作都有确认。
- 本地数据可持久化。

只要这个闭环稳定，就能在一天内交付一个完整、有亮点、可演示的 Agent 应用。
